collector#138 — the Triage button's session loads the triage skill
==================================================================

Proof run: 2026-11-13, on altair, by hand — the card allows "the pane command run by hand"
instead of a real click. The live Collector on port 4000 serves the build from before this
card, so a click there would run the old prompt.

The Triage button's session is `openFixPane(TRIAGE_KEY, triagePrompt(card), ...)`
(`app/api/debug-fix/route.ts`), which starts the pane with `tmuxArgs(homedir(), prompt)`
(`lib/server/debug-fix.ts`): cwd `$HOME`, as the card asks.

1. The pane command, run against a tmux session of this run's own (name `collector138`), never
   James's pane. `-t collector138:` is the only addition to the argv `tmuxArgs` builds:

   tmux split-window -t collector138: -h -c /Users/james -P -F '#{pane_id}' /bin/zsh -lc \
     'PATH="$HOME/.local/bin:$PATH"; exec pi --provider claude-code --model claude-opus-5-5 "$0"' \
     '/skill:triage Triage dividendsolo/omarchy4mac#45 with James. It is the one card in
      needs-triage on the board. ... 6. Then run the after-triage-sweep skill on the same repo.'

2. pi expanded the skill into that pane session's first message. From the pane's own session
   file (~/.pi/agent/sessions/--Users-james--/2026-11-13T16-53-46-952Z_01a1d5d4-....jsonl),
   first user message, 7341 bytes:

     <skill name="triage" location="/Users/james/.claude/skills/triage/SKILL.md"> ... # Triage ... </skill>
     /skill:triage Triage dividendsolo/omarchy4mac#45 with James. ... 6. Then run the
     after-triage-sweep skill on the same repo.

   So the pane's pi finds the skill: `~/.pi/agent/settings.json` names `~/.claude/skills` under
   `skills`, and pi reads it whatever the pane's cwd is. No change to `tmuxArgs` was needed.

4. The line rule the prompt has to keep. pi reads the skill's name up to the first space of the
   whole message. The same prompt with `/skill:triage` alone on its first line does not expand —
   pi sent 60 bytes with no skill block, and the model answered "I don't have a `triage` skill
   loaded." The request therefore starts on the command's own line, which is the form pi
   documents: `/skill:name <request>`.
