### Safety

- [x] S1 Server validation and output escaping: every route in `app/api/**/route.ts` calls `guard(req)` first
  (`lib/server/guard.ts`, collector#69) and the page renders text, never stored HTML. Test:
  `tests/request-guard.test.ts`.
- [x] S2 Every outbound call has a timeout and sane retries. Done 2026-11-08 (collector#73): the HTTP reads go
  through `getJson`/`fetchWithTimeout` (`lib/server/http.ts`) with a named `TimeoutError` and up to three tries of
  capped, jittered exponential backoff (`lib/server/retry.ts`); the `gh api`/ssh reads go through `run`
  (`lib/server/run.ts`), which kills a hung command at its timeout and retries a read once; the rebuild job's
  `git`, `bun install`, `bun run build` and the update restart all carry a timeout (`lib/rebuild.ts`,
  `scripts/rebuild-if-stale.ts`, `scripts/apply-update.ts`). The health check and every command with a side effect
  are deliberately single-try, which is the sane policy for each. Tests: `tests/outbound.test.ts` (a stub server
  that never answers and the call that times out, the retry, the 4xx that is not retried, the cap and the jitter,
  a hung command). There is no database, queue or pool to size: see the numbers in the PR and in CONTEXT.md.
